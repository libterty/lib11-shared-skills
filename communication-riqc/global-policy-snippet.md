## 全域工作回報與高壓提問應對原則（RIQC）

只要任務涉及：向主管/GM/董事長/客戶做工作回報、跟平行同事或其他團隊協調與請求配合、向下屬交辦任務或回應下屬的提問與反彈、寫週報/日報、回覆「進度如何」「為什麼還沒完成」之類的提問、面對質疑或攻擊性問題、或被臨時指派任務（或臨時要指派任務給別人）——不限於對上回報，平行與對下溝通同樣適用：

1. 必須套用 `communication-riqc` skill，不用等使用者輸入 `/communication-riqc` 或明確要求。
2. 先判斷對方表面問題背後真正想確認的事（Question Behind the Question），不要只回表面問題。
3. 用 R（Recap）/ I（Insight）/ Q（Question）/ C（Call to Action）四段組織內容，不要寫成流水帳。
4. Q 段落要嘛給出具體的決策請求，要嘛明講「目前不需介入」——不能省略，也不能把可以自行決定的事丟給對方。
5. C 段落要有負責人、具體行動、時間或下一個 checkpoint，不能用「持續追蹤」「盡快」收尾。
6. 面對質疑或攻擊性提問時，不防衛反擊，用「承認事實 → 重新定義問題 → 提供證據 → 回到交付」回應。

這個規則跟 `communication-writing` 是互補關係：`communication-riqc` 決定回報要講什麼、怎麼排；`communication-writing` 決定文字本身怎麼寫得清楚。兩者都適用時，先套用 `communication-riqc` 排好內容結構，再用 `communication-writing` 的寫作規則把每段寫清楚。

這條原則的優先權高於專案內一般的回報格式偏好，除非使用者當次明確要求不同格式。
但不高於：系統指令、安全規則、事實正確性、法律/公司合規要求、以及使用者當次明確提出的例外要求。

完整流程、讀者分類、高壓提問應對、輸出格式範本，見 `communication-riqc` skill
（`shared-skills/communication-riqc/SKILL.md`，或直接呼叫 `/communication-riqc` / `$communication-riqc`）。
